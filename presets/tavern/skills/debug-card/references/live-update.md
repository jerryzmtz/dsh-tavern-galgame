# 修改后在原存档继续玩

目标是修改资源后回到原游玩会话，点击「应用变化到当前游戏」，继续剧情。状态栏、EJS、世界书与变量结构一起预检，通过后原子应用；失败时保留上次已应用的定义与变量。新定义不会重新执行开场初始化来覆盖游戏进度。

## 修复流程

1. 从已引用的 `play-chat:` 读取当前变量与异常证据，再读取人物卡、世界书的对应定义。
2. 修改状态栏 HTML/CSS、正则或 EJS 时保留状态栏声明与稳定的正则 id。EJS 展示使用当前变量；更新预览的变量写入被隔离，外部写入与命令不允许在预览执行。需要改变游戏状态的逻辑放在正常结算中。
3. 新增变量补默认值，已有数值继续保留。修改默认值不会重置旧存档。字段改名、移动、删除、类型变化时，在同次卡片修改中提供下述迁移声明，并同步世界书初值与更新规则。
4. 告知用户返回原游戏应用变化。若预检指出具体路径冲突，修复迁移声明后重试；不通过重开游戏掩盖迁移缺失。没有实测应用和继续下一轮时，报告“资源已修改，待应用验证”。

## 变量迁移声明

写入人物卡 `extensions.dsh_tavern.stateMigrations`，通过 `tavern_update_card` 的 rawOperations 修改对应路径。V2/V3 原始文件通常是 `/data/extensions/dsh_tavern/stateMigrations`；先读取原始结构确认。保留已有声明，为新迁移使用新 id，已执行的 id 对应内容不可改变。

```json
[
  {
    "id": "wallet-v2",
    "operations": [
      {"op": "move", "from": "/gold", "path": "/wallet/coins"},
      {"op": "convert", "path": "/rank", "type": "number"},
      {"op": "remove", "path": "/obsoleteFlag"}
    ]
  }
]
```

路径相对于 `stat_data`，使用 JSON Pointer（`~1` 表示 `/`，`~0` 表示 `~`）。支持对象字段及嵌套对象；数组内字段、数组重排和任意脚本转换暂不支持，遇到这些变化先保留旧结构，修正展示或规则以继续玩。

- `move` 保留原值，目标已存在则拒绝，避免覆盖另一笔进度。
- `convert` 支持 string、number、boolean。数值字符串可转数值，布尔转换仅接受 true/false 及其字符串；不猜测单位或语义。
- `remove` 仅用于用户明确不要的字段，同时移除初值定义，否则新增字段规则会将其补回。
- 迁移应用于每个已有 MVU 快照，包括历史回合、候选 swipe、回退检查点和撤销回退数据，使旧回合继续兼容新版结构。原来的历史数值保留，只有声明的字段变换及新增默认值改变快照形状。
- 修改初值中已有字段的名称，必须声明 move；直接新增新名称、删除旧名称会被预检拦截，避免把玩家余额当成新字段重置。

验收至少核对：原 chat/session 不变、已有正文不变、当前数值延续、新状态栏出现、刷新不重复产生 EJS 副作用、新一轮结算成功、回退后仍显示正确数值。存档救援用于旧对话本身无法继续的情形，不是普通改卡流程。

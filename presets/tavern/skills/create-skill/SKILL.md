# Tavern Skill Creator

采用 Codex skill-creator 的编写方法，为 Tavern Agent 提供有用、非显而易见的指导。成品通过 `tavern_save_skill` 保存到 Tavern Skill 库。

用户明确引用教学素材制作场景写作 Skill 时，加载 `create-writing-skill`，由它处理材料依据、场景边界和用户意见；本 Skill 提供通用组织与验证方法。写作 Skill 使用独立的完整正文，不拆 references；下文参考文件的组织方式适用于其他确有需要的 Skill。

## 编写原则

- **假设 Agent 已有能力。** 只写会改变决策或改善结果的信息，删去通用常识、重复说明和没有实际用途的例子。
- **保留用户意图与范围。** Skill 支持原任务，不扩大授权、不修改无关配置；一次失败或某个案例不能直接变成所有任务的强制规则。
- **具体程度匹配风险。** 开放式任务描述目标和取舍；只有脆弱接口、真实限制或确定性要求才规定固定顺序。区分硬约束、建议和例子。
- **发现准确、加载渐进。** 简介负责识别何时使用；入口保留共有方法和必要边界；只有当前任务需要时才加载详细参考。
- **独立可用。** 所需材料随 Skill 保存；引用其他 Skill 或工具前，确认目标 Agent 确实能使用它。

## 创建或修改

### 1. 明确真实用途

从用户当前请求和已有材料确定：什么输入会触发它、需要交付什么、什么情形不适用。信息已经充分时直接编写，关键边界影响结果时再询问。

以实际请求检验可复用性：一次性正文、人物卡字段或纯资料未必需要独立 Skill。修改已有 Skill 时先读当前正文和参考文件，保留用户未要求改变的能力与调用策略。

### 区分流程与改卡经验

用户要求记住改卡偏好时使用 `tavern_memory_preference`；记录报错、失败尝试或修复经验时，先 `tavern_memory_search` 查重，再用 `tavern_memory_experience` 新建或更新。具体卡片默认 `scope=card`，未确认的原因或方案标记 `unverified`。这些记录不需要创建 Skill，也不主动建议把每次报错做成 Skill。

仅当用户明确要求把经验提炼成可复用任务流程时，继续本 Skill。提取触发条件、排查步骤、已验证处理和验证方法，明确未验证边界，避免把单次失败推广成所有卡片的限制。先查找已有相关 Skill，按授权补充或派生，移除密钥、私人对话和无关卡片正文。

### 2. 选择组织方式

简单方法可以只有一个入口，长度以任务需要为准。入口写目标、关键判断、执行方法和完成标准，不必套用固定章节或步骤数量。

只有存在实质不同的场景、流程或长篇教学时才拆出 `references/*.md`。在入口用相对链接说明**何时读取哪份资料**，运行时通过 `tavern_read_skill_reference` 按需加载。避免入口和参考重复，也不要默认要求读完全部文件。

例如，分别处理调查场景与追逐场景的方法，可以在入口列出选择条件，将各自详细教导放入两份参考文件；一个简短且统一的方法无需拆文件。

把运行必需的教导、例子和模板内容写入正文或参考文件。删除原始素材后，Skill 仍应完整可用。当前保存接口只打包正文和 Markdown references；不要承诺随包保存 scripts、assets 或 Codex 的 `agents/openai.yaml`。确实需要可执行工具的需求，先按 Tavern 高级扩展流程确认能力与范围。

### 3. 编写发现信息与指令

名称使用简短的 kebab-case。简介说明实际能力和触发场景，只有容易误触发时才加入排除条件，避免罗列所有能力或使用“任何任务”之类兜底描述。

正文使用可执行的指令和可检查的结果。把条件与对应动作写在一起，给出真正影响选择的例子；环境能直接提供的工具参数无需复制成整份手册。

默认允许模型发现和用户显式调用。仅当用户明确要求手动调用时关闭 `modelInvocable`；Skill 可被发现不等于获得额外写入或外部操作授权。

## Tavern 保存适配

用户已要求创建或修改时执行保存；仅讨论或审阅方案时展示草稿。

- 提交 `name`、`description` 和完整 `body`。`body` 只含 Markdown 正文，YAML frontmatter 由保存接口生成。
- 按用途设置 `purpose`：`card` 为卡片制作、`writing` 为前台写作、`background` 为后台任务、`image` 为文生图。省略 `agents` 时按用途分配；只有用户要求其他分配时才指定。
- 参考文件以 `references` 数组提交，每项为相对 `path` 和完整 `content`。修改时省略数组会保留旧参考；传入数组会替换整套参考，先读取并保留仍需要的文件。空数组表示清空参考。
- 修改同名用户 Skill 时设置 `overwrite: true`。内置 Skill 不能由该接口覆盖；需要派生版本时使用新名称并说明关系。
- 保存到 Tavern，不使用 Codex 的个人目录、初始化脚本或 UI 元数据机制代替此接口。

## 验证与迭代

保存前检查发现信息是否能区分相邻任务，正文是否保留用户意图，参考链接是否齐全，目标 Agent 是否具备所需工具。保存接口的格式校验不能证明 Skill 的行为正确。

对复杂或实质性改写，选取真实的适用请求与一个容易混淆的不适用请求，检查触发选择、按需读取和输出是否符合目标。有条件且获得授权时在隔离环境实际试用；小幅措辞修改不必强制完整演练。不要用匹配固定标题或句子的测试冒充效果验证。

根据实际结果修正具体问题，避免每次失败都累加全局禁令。保存后简短报告名称、用途、是否覆盖，以及实际完成的验证；未试运行的部分如实说明。

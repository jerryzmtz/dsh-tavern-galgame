# 人物卡加 MVU

目标：前台写剧情，后台按规则更新变量，状态栏读取变量显示。格式约定见 [MVU 卡格式约定](references/mvu-format.md)；用 `tavern_apply_mvu` 写入时不必先读，自己写面板 HTML 或绕开工具直接改卡时再读。

## 做法

1. 读卡：先 `tavern_mvu_overview` 看全貌（开场、世界书、正则、脚本，并标出可能的旧状态协议），再按需用 `tavern_read_card`、`tavern_read_card_raw` 读具体内容，找出随剧情变化的状态（时间、地点、关系、物品、线索等）。固定设定留在原文，不必搬进变量。
2. 决定改哪张卡：新建的卡直接在原卡上改；用户要保留原卡时先 `tavern_copy_card` 建副本，再改副本。
3. 设计并写入：用 `tavern_apply_mvu` 一次给出变量默认初值、各开场与默认不同的值、更新规则和面板。工具负责把 `<initvar>`、`<mvu-status/>` 放进每个开场，建好 `[mvu_update]`/`[initvar]` 条目和两条正则，不必重写开场正文，也不必手写这些格式。
   - 变量：各开场字段结构一致，值按场景填；未知写明确的空值。
   - 规则：讲清每个字段在什么剧情事实下怎么变。
   - 面板：按题材选主色、分组和字段（`bar` 进度条、`list` 列表）即可得到标准面板；想要更有特色的观感，或原卡已有状态栏美化要改造成读 MVU 变量，就在 `panel.html` 里写完整 HTML。
4. 清理旧协议：原卡里要求模型在正文输出状态块的说明、开场里的示例状态块和对应正则，整条删除的可在同一次 `tavern_apply_mvu` 里用 `remove` 一并删掉；需要改写的用 `tavern_replace_card_text`、`tavern_update_worldbook`。与状态无关的美化、脚本、正则保留。
5. 校验：保存工具结果已附带校验；修正全部 errors，再看 warnings 是否需要处理。之后要细调任何一部分，可再次调用 `tavern_apply_mvu` 只传那一部分，或用其他工具直接改。

改哪里、怎么改由你判断，按改代码的方式一次改完再校验，不必拘泥步骤顺序。校验只覆盖静态格式，不代表真实游玩已经验证；用户要求时才做真实试玩。
